# Shikshaq: context

## In plain words
- Shikshaq is a tuition-finder website for Kolkata. Families browse tutor profiles by subject, board (ICSE, ISC, CBSE and others) and locality, and read free past-paper banks.
- People who use it: students and guardians (parents) who look for tutors and read papers, teachers who list themselves and pay attention to reviews, "checkers" (paper verifiers) and HODs (heads of department) who review question papers, a games team that writes practice questions, reviewers who handle teacher applications, and admins.
- An AI FAQ chatbot (Google Gemini, called through a small server function) answers questions and can suggest approved teachers.
- It runs on a React and Vite website hosted on Vercel, with Supabase as the database, login, file storage and background functions. The live site builds from the `main` branch; a test deployment shares the same Supabase project.
- The codebase is large (about 1,046 files). Several database and security notes below are open issues the owner should read before changing anything.

## How to run it
- Install: `npm i`. `run-dev.bat` runs `npm install` on every launch (Windows).
- Dev server: `npm run dev` (port 8080; the `PORT` variable overrides it).
- Tests: `npm test` (runs `vitest run --exclude ".claude/**"`); watch mode with `npm run test:watch`.
- Lint: `npm run lint`. Typecheck: `npx tsc -b`. Do not use root `npx tsc --noEmit`; the root tsconfig has `files: []` and checks nothing.
- Build: `npm run build` runs the prebuild generators, then `vite build`, then `tsx scripts/prerender.ts`. It needs live Supabase variables. `npm run build:dev` skips the prebuild hooks.
- Preview: `npm run preview` (CLAUDE.md says port 4180).
- Data scripts: `generate-sitemap`, `generate-blog-stats`, `generate-locality-pages`, `generate-figure-dimensions`, `generate-bank-sql`, `import-bank`, `test:gemini`.
- Deploy: `npm run push:all` pushes `shikshaq-2.0` to origin and `main` to the test remote. Launch steps are in `docs/LAUNCH.md`: open a PR into `main` with `gh pr create`, then `gh pr merge` (fast-forward). Vercel builds `main`. Rollback tag: `pre-2.0-live`.
- CI: `.github/workflows/ci.yml` runs `npm ci`, `npx tsc -b`, `npm test` and `npx eslint .` on Node 20. There is no build step in CI.
- Setup guides in the root: `GOOGLE_AUTH_SETUP.md`, `LOCALHOST_AUTH_SETUP.md`, `GEMINI_CHATBOT_SETUP.md`, `ADMIN_SETUP_DATABASE.md`, `VERCEL_SETUP.md`, `SUPABASE_RUNBOOK`, `GUARDRAILS`, `SEO_STRATEGY`.

## Main flows
1. Chatbot. `src/components/Chatbot.tsx` answers common questions from a local list after about 300 ms. Otherwise it POSTs `{ message, history }` to `/api/chat` with a 15 second abort, and shows teacher rows with `TeacherCard`. On the server, `api/chat.ts` (`handler`) tries Gemini models in order, each raced against a 15 second timer. If the message has a find-teacher word and a subject keyword, `findMatchingTeachers` queries `subjects`, then `teachers_list` (limit 3), then `Shikshaqmine`. The reply is `200 { response, teachers }`. In development, `vite.config.ts` (`vercelApiDevPlugin`) loads the same handler.
2. Build and prerender. Prebuild generators (`scripts/generate-locality-pages.ts`, `scripts/generate-sitemap.ts` and others) read Supabase and write `src/content/*.generated.ts` and `public/sitemap.xml`. Then `vite build`. Then `scripts/prerender.ts` writes `dist/<route>/index.html` for about 1,700 routes and checks that no question text leaked.
3. Question bank. JSON in `data/question-bank*.json` goes through `scripts/convert-subject-bank.ts`, then either `scripts/import-bank.ts` (service-role upsert into `bank_papers` and `bank_questions`) or `scripts/generate-bank-sql.ts` (writes `supabase/bank-import.sql`). `scripts/generate-blog-stats.ts` writes `src/content/blog-stats.ts`, which feeds `blog.ts`. `generate-blog-nav.ts` writes `blog-nav.ts` for `Footer.tsx`.
4. Subject and board SEO. `src/content/subject-meta.ts` and `subject-seo.ts` feed `SubjectPage.tsx`, `BoardPage.tsx` and `SEOContentBlock.tsx`. `scripts/prerender.ts` reads the same data (around line 634).
5. Locality pages. `scripts/locality-data.ts` reads published, unpaused teachers with the anon key. `generate-locality-pages.ts` keeps subject and area pairs with at least 5 teachers (104 pages). The output feeds the `App.tsx` routes, the sitemap and prerender.
6. Sitemap. `scripts/generate-sitemap.ts` reads `teachers_list`, `papers`, `Shikshaqmine` and `bank_papers` (through `sitemap-bank-urls.ts`, which drops 24 IDs listed in `excluded-papers.ts`). It writes `public/sitemap.xml` and fails if there are fewer than 900 URLs.
7. Sign-in. Supabase Auth with the Google provider, plus email and password, magic link and reset. `src/lib/auth-context.tsx` checks `check_user_exists` and `check_user_has_password` on sign-up, then calls `signUp`. Sign-in uses `signInWithPassword`. `src/lib/auth-intent.ts` keeps the intended action for 10 minutes. Site URL and redirects switch between localhost:8080 and the Vercel host (see the auth setup guides).
8. Sign-up and role. `src/pages/Auth.tsx` signs in or up, then reads `profiles`. No role sends the user to `src/pages/SelectRole.tsx` (which upserts `profiles`). A teacher without accepted terms goes to `src/pages/TeacherTermsAgreement.tsx`. Otherwise the user goes to the saved redirect or the home page for their role.
9. Find a teacher. `src/pages/Index.tsx` or `src/pages/Browse.tsx`. Browse prefilters `Shikshaqmine` with an ILIKE query when structural filters are set, filters on the client (`src/lib/teacher-facet-match.ts`), then fetches `teachers_list` by slug in chunks (`src/lib/teachers.ts`). The search index (`src/hooks/useSearchIndex.ts`) is capped at 2,000 teachers and 500 papers.
10. Contact a teacher. `src/pages/TeacherProfile.tsx` shows a WhatsApp button. A signed-out visitor sees `src/components/ContactGateSheet.tsx` and a sessionStorage flag. A signed-in visitor goes to `src/pages/WhatsAppRedirect.tsx`, which records the click and forwards to WhatsApp after 500 ms. The heart button in `TeacherCard.tsx` sends signed-out users to `/auth` and otherwise calls `toggleLike`.
11. Reviews. `src/components/TeacherComments.tsx` reads `teacher_comments_public` and `public_profiles`, keeps approved rows plus the viewer's own, and posts into `teacher_comments` with approved set to the inverse of anonymous. Admins publish or remove them in `src/pages/admin/reviews.tsx`.
12. Recommend a teacher. `src/pages/RecommendTeacher.tsx` inserts a pending row in `teacher_recommendations`. An admin marks it contacted, dismisses it, or converts it to an application in `src/pages/admin/reviews.tsx`.
13. Apply to teach. `src/pages/Join.tsx` sets the auth intent, then `src/pages/JoinApply.tsx` (five steps, draft in sessionStorage) uploads the photo, inserts one `teacher_applications` row with status pending, and shows a review screen. An admin decides in `src/pages/admin/approvals.tsx` (RPC `approve_teacher_application`; reject is a conditional update).
14. Read a paper. `src/pages/PastPapers.tsx` or the home shelf leads to `src/pages/PaperResults.tsx`, then the paper page. `/past-papers/:id` shows `PaperReader` for a UUID and `BankPaper` otherwise. A signed-in reader gets the PDF in an iframe after `PaperReader` upserts `paper_reads` and calls the `paper_file_url` RPC. A signed-out visitor sees a blurred page and a sign-in gate. `BankPaper.tsx` shows questions; signed-in users can report one into `question_reports`.
15. Submit a paper. `src/pages/SubmitPaper.tsx` uploads up to a set number of PDF or image files (25 MB each) to the `paper-submissions` bucket, then inserts `paper_submissions` with status pending. On failure it shows a WhatsApp fallback.
16. Checker verdict (paper verifier). `src/pages/Checker.tsx` checks `api.isPaperChecker`, then renders `src/components/checker/VerifyScreen.tsx`. `planAnswer` in `src/lib/checker-drafts.ts` picks pass or fix. `checkerSaveRoute` in `src/lib/checker-save.ts` picks locked, legacy or refuse. The outbox (`src/lib/checker-outbox.ts`) writes to localStorage first, then sends one verdict per paper through `sendVerdict`. `src/lib/checker-verdict-next.ts` builds and parses the `verifier_verdict_and_next` RPC. On a failed send, `src/lib/checker-advance.ts` decides whether to re-read the paper. Definite refusals stop; other errors retry with backoff. Realtime updates come from `src/hooks/usePaperReviewChannel.ts`.
17. Checker pictures and prefetch. `src/lib/checker-pictures.ts` chooses the crop, reusing a warm link from `src/lib/checker-prefetch.ts` or calling the picture RPC, cached by `src/lib/checker-picture-cache.ts`. `prefetchNext` signs up to six upcoming questions in one call. `src/lib/checker-page.ts` allows a whole-page fallback only when the source is marked page-verified.
18. Checker practice. `src/pages/CheckerPractice.tsx` runs an offline round from `src/lib/checker-practice.ts`. It must never reach Supabase and stores nothing.
19. HOD desk. `src/pages/Hod.tsx` checks `api.isHod` and renders tabs from `src/components/hod/` (NeedsYou, Ready, Live, Assignments, Verifiers, Uploads, History, AiTrust). Data comes from `src/lib/hod-api.ts`. `canPublishNow` in `src/lib/hod-publish.ts` gates publishing. `grantHod` and `revokeHod` (`src/lib/hod-admin-actions.ts`) call RPCs and then write an audit entry.
20. Admin approval. `src/lib/admin-approval.ts` calls `admin_*` RPCs. Results go through normalisers in `src/lib/admin-approval-shape.ts`. `changesFromDraft` sends only changed fields. `src/components/admin/approval/ReviewQuestionCard.tsx` edits a question, and `QuestionVersions` shows history and reverts.
21. Admin gate and sections. `src/components/AdminConsole.tsx` `useAdminGuard` selects `admins` by user id (12 second race), then redirects to `/auth` or `/`. `src/pages/admin/index.tsx` shows four tabs (People, Teachers, Logs, System). Admin counts come from `admin_nav_counts` in `src/pages/admin/useAdminSectionCounts.ts`.
22. Games writer. `src/pages/games/WriteQuestions.tsx` (in `src/components/games/`) sends the draft to a 450 ms debounced `GamePreview`, then `Revise`, then `GameView`. Sending calls `api.sendBatch`. `Chapters` saves through `api.saveChapters`. `TryGames` loads `loadQuestionBank`. `src/lib/games/engine/index.ts` `makeGame` tries up to 12 seeds and returns only a puzzle that passes its checker.
23. Errors and stale builds. `src/components/ErrorBoundary.tsx` logs through `logger.error`. It reloads at most once per minute for stale-chunk errors, sharing that budget with the `vite:preloadError` listener in `src/main.tsx` (`claimStaleChunkReload`).
24. Scroll and tour. `src/components/ScrollManager.tsx` (mounted in `App.tsx`) sets manual scroll restoration and keeps positions in sessionStorage. `src/components/ProductTour.tsx` opens on the first visit or on the `shikshaq:open-tour` window event.

## Data
Tables grouped by purpose. This is the current state; the supabase digest is the authority on what is applied.

**Profiles, roles and admin**
- `profiles`: one row per auth user. Holds full name, email, role (student, guardian, teacher, admin; nullable), terms agreement and personal fields. Clients cannot set the teacher or admin role (trigger `prevent_role_escalation`). Read and written by `src/pages/Auth.tsx`, `SelectRole.tsx`, `Account.tsx`, `TeacherTermsAgreement.tsx`, `GuardianDashboard.tsx`, `StudentDashboard.tsx` and `src/lib/auth-context.tsx`. Some pages still select `*` from it.
- `admins`: admin list by user id. `is_admin()` checks only this table. Read by `AdminConsole.tsx` and `useIsAdminBadge`.
- `teacher_reviewers`, `paper_checkers`, `paper_hods`, `checker_assignments`, `verifier_profiles` (grade 1 to 17, preferred subjects, valid_until), `paper_checker_prefs` and `distribution_throttle` (no client grants): checker, HOD and reviewer roles, and the paper hand-out state.
- `pending_role_grants` (email, role): applied by a trigger on auth.users when a user confirms sign-in. Errors are swallowed.
- `positions` tables and `admin_position_holders` RPCs: role grants used by `src/lib/positions-api.ts`.

**Teachers and directory**
- `"Shikshaqmine"`: the legacy teacher master sheet (Title, Slug, Email ID, Link, Phone, MOU, fees, Area, Place of Teaching, is_paused, "Classes Taught", "Sir/Ma'am?"). Written by `TeacherDashboard.tsx` and the admin `teachers.tsx`. Contact columns are column-gated. The quoted, mixed-case names must be kept exactly.
- `teachers_list`: the public directory, synced from `Shikshaqmine` by the RPC `sync_teachers_list_from_shikshaqmine` (location comes from Area). Fields include name, slug, approved, location, subjects, classes, image_url, is_featured and updated_at. `whatsapp_number` is no longer readable by clients.
- `subjects`: name and slug. `teachers` and `testimonials` (migration 20251218160257): applied state unclear.
- `teacher_applications`: applications with status, reference fields, texted_status and fees. Inserted by `JoinApply.tsx` and `reviews-admin-api.ts`; read and updated in `src/pages/admin/approvals.tsx` and `src/lib/admin-applications.ts`.
- `teacher_recommendations`: recommendations (admin-only). Written by `RecommendTeacher.tsx`.
- `teacher_upvotes` (write), `teacher_upvote_stats` (view), `liked_teachers`, `student_teachers`: saves and likes. Read by `src/lib/use-toggle-relation.ts` and the `likes-context` and `upvotes-context` providers.
- `teacher_comments` (only approved, non-anonymous rows are public), `teacher_comments_public` (view), `public_profiles` (view of review authors).
- `profile_views` (teacher slug; written by anonymous visitors) and `whatsapp_clicks` (teacher slug; written by anonymous visitors). Read for counts in `TeacherDashboard.tsx`.
- `page_content`: footer blocks and help topics, read by `Footer.tsx` and `useHelpTopics`.
- `feedback`: guest and member feedback, inserted by `FeedbackModal.tsx`, read and deleted by `src/lib/feedback-admin-api.ts`.
- `student_subjects`, `guardian_student_subjects`, `guardian_student_relationships`, `student_teachers`: student and guardian links (delete then insert).

**Papers and question bank**
- `bank_papers` and `bank_questions`: the public library. Paper metadata includes year (a string here; a number in `papers`), school, `needs_review` and `is_published`. Clients have no table SELECT on `bank_questions`. Reads go through `bank_paper_questions(text)`, `bank_paper_visible_counts` and `site_counts()`. Read by `src/lib/question-bank.ts`, `src/pages/BankPaper.tsx` and prerender. Writes are admin-only through RPCs.
- `papers`: an older paper table (year as a number), read on most public pages. The paper-search code in `src/hooks/useSearchIndex.ts` reads it with `is_published = true`.
- `paper_reads`: upserted by `PaperReader.tsx`; `paper_read_stats` (view).
- `question_reports`: written by `BankPaper.tsx`.
- `paper_submissions`: student uploads (status pending). Written by `SubmitPaper.tsx`, read by HODs.
- `paper_registry`: one row per source PDF, with a state check. Read and written by `src/lib/paper-registry*.ts`.
- Pipeline staging (admin and service-role only): `audit_papers`, `audit_questions` (lease, verdicts, set-aside, raw OCR, AI confidence), `audit_paper_pages`, `audit_question_skips`, `audit_review_log` (append-only; undo via counted views), `bank_question_revisions`, `content_versions`, `content_checks`, `ai_trust_levels`, `paper_files`. Read through `src/lib/audit-api.ts`, `src/lib/pipeline-api.ts` and `src/lib/question-timeline.ts`.
- Key RPCs: `paper_file_url(uuid)`, `bank_paper_questions(text)`, `checker_next_question()`, `verifier_verdict_and_next`, `verifier_undo_last`, `verifier_reopen_question`, `verifier_peek_next_in_paper`, `paper_page_pictures`, `distribute_unassigned_papers()` (scored hand-out), `explain_assignment`, `approval_publish_paper`, `hod_approve_paper(uuid, text, boolean)`, `hod_paper_trail()`, `admin_pipeline_route()`, `admin_approval_queue`, `admin_paper_review`, `admin_approve_paper`, `admin_edit_question`, `admin_revert_question`.

**Games (games schema, RPC only)**
- `games.settings`, `games.team` (email, role admin, hod or member, moderator flag), `games.boards`, `games.subjects`, `games.chapters`, `games.topics`, `games.batches`, `games.questions` (every submission and its status), `games.question_bank` (approved only), `games.list_log`. Installed by `supabase/games/install.sql`. Not yet exposed to the app beyond RPCs.
- Key RPCs: `submit_batch(jsonb)`, `bank()`, `catalog()`, `hod_set_status`, `hod_questions`, `admin_save_chapters`, `my_role`.

**Admin, audit and telemetry**
- `admin_audit_log`: append-only; admins can select and insert. Written by `src/lib/audit.ts` and read (newest 500) by `src/lib/audit-api.ts`.
- `log_action_catalog`: allowed audit action names.
- `read_events` (per-read telemetry with ip_hash; kind `paper` rows reveal which papers were opened), `read_quota_config` (enforcing = false), `read_quota_exempt`, `read_quota_breaches`, `read_events_retention`. No client grants.
- `rate_limit_log`: rate limiting for RPCs. `feedback` as above.
- Backups: `_dash_backup`, `_backup_english_*` and `audit_*_backup_20261012` tables. Closed to clients; several hold question text.

**Storage buckets**
- `hero-images`: public read, admin write. Anonymous insert by prefix is allowed (see Watch out).

- `paper-submissions`: private student uploads; signed URLs last 600 seconds.
- `paper-figures` (public URL built as a string), `audit-figures` (private; signed URLs 600 seconds), `paper-ocr`.

## Who can see what
- **Anonymous visitors (signed out)**: read `public_profiles` (name, role, school or college, grade, avatar) for authors of approved non-anonymous reviews; read approved comments and the `teachers_list` directory minus WhatsApp numbers; read published bank questions only through `bank_paper_questions` (two per paper when signed out; none for unpublished or `needs_review` papers). They can call `site_counts()`, `teacher_whatsapp_link` (returns null), `paper_file_url` (returns null), `check_user_exists` and `check_user_has_password` (rate-limited, needed for sign-in). They can insert teacher applications (email format, 3 per email per 24 hours), guest feedback, `profile_views` rows, `paper_submissions` rows (status pending only), and upload to `hero-images` by prefix. They cannot read `bank_questions`, `read_events` or contact columns.
- **Signed-in users**: read and write their own profile, comments, likes, student or guardian rows, feedback and `paper_reads`. They read full bank paper questions and their own applications (by email), upvote and remove their own upvotes. Teacher recommendations are admin-only.
- **Teachers** (role teacher, matched by profile email): select and update their own `Shikshaqmine` row, but Title, Slug, Sir/Ma'am, EXPANDED and Email ID are reverted by trigger. They read their own contact through `teacher_own_contact()`. They see `profile_views` for their own slug.
- **Checkers (verifiers)**: active paper checkers, including active HODs, use `checker_*` and `verifier_*` RPCs on assigned papers only. They read `audit-figures` only for papers they hold. They have no direct table writes. Legacy checker RPCs were revoked.
- **HODs**: all checker rights plus HOD RPCs (approve, live edit, assign, registry, trail). They can read the `paper-submissions` bucket, which holds strangers' uploads.
- **Teacher reviewers**: read applicant and listed-teacher phone and email through definer functions; can edit most listed-teacher fields (not slug, email, contact or pause state).
- **Admins**: `is_admin()` gates admin RPCs, `admin_audit_log` and the admin-only tables. Bank tables are select-only for admins; writes go through admin RPCs with validation.
- **Service role and cron**: pipeline functions, `distribute_unassigned_papers_cron` (every 2 minutes), AI batch functions and `pipeline_update_live_paper`.
- **Nobody on the client**: `read_events`, `read_quota_*`, `pending_role_grants`, backups, `distribution_throttle`, and the `games.*` tables (revoked; RPCs only).
- **Browser-only checks are not security.** `src/components/AdminConsole.tsx` checks admin status in the browser. `Admin` and `HOD` badges are display-only. Real enforcement is in database policies and RPCs (the RLS checks are not verified in the review).

## Conventions
- Two git remotes (origin for live, and the test remote) must hold identical commits. The working branch is `shikshaq-2.0` (per CLAUDE.md, README and AGENTS.md).
- `VITE_` values are public. Secrets are server-only. CLAUDE.md forbids putting passwords under `VITE_` names.
- Generated files (`*.generated.ts`, `blog-stats.ts`, `blog-nav.ts`, `figure-dimensions.ts`, `public/sitemap.xml`) are regenerated, not hand-edited.
- Style: Tailwind tokens from `tailwind.config.ts`; `DESIGN_SYSTEM.md` is the contract; warm neutrals; Geist body and Archivo display; no stock photos; no em or en dashes in reader-facing copy. Copy is plain words with no snake_case and no UUIDs, checked by tests that grep source text.
- Tailwind utilities use brand tokens (`bg-panel`, `text-brand-foreground`, `hsl(var(--foreground))`). `src/components/ui/` primitives use `cva` and `cn` from `@/lib/utils`. A few files hard-code hex colours (alert-dialog, sheet, sonner, paper-cover, ChangeView, AuthHero).
- The `@/*` alias maps to `src`. The app tsconfig is loose (`strict: false`); the node tsconfig is strict.
- ESLint: `no-explicit-any` is a warning; `no-unused-vars` is off.
- File names: PascalCase in most `src/components` folders; kebab-case in `papers/`, `reviews/`, `teacher-review/`, `join/`, `marketing/`, `seo/` and the `*-fake-api.ts` dummies. Components use named exports; a few add default exports (`ErrorBoundary`, `DelayedFallback`, `SEOHead`).
- Injected API pattern: pages and components take API objects as props (`CheckerApi`, `GamesApi`, `HodApi`, `ApprovalApi`, `TeacherReviewApi`). The fakes in `src/dummy/` implement the same interfaces, so real pages run unchanged.
- Each `src/lib` module has a pure logic layer, a `real*Api` wrapper that calls Supabase, and a fake in `src/dummy/`.
- RPC wrappers call `supabase.rpc(name as never)`, throw on error and return data. Normalisers are deliberately forgiving (bad values become 0, null or a default). Almost every RPC call uses an `as never` cast because the generated types are out of date.
- Storage access is wrapped in try/catch; keys use the `shikshaq` prefix; the data is device-local only.
- Data fetching uses React Query with scoped keys; module-level caches hold indexes and footer content.
- Gates: `PREVIEW_TOOLS` (`src/lib/preview-tools.ts`), `import.meta.env.DEV`, and `?dummy=1` (with a sessionStorage flag) for dummy mode. Admin and HOD badges are display-only, not authorization.
- Testing: Vitest; markup rendered with `renderToStaticMarkup`; the Supabase client is mocked. Many tests are static and read source files with `readFileSync`. CI has no database, and several tests use relative paths that fail outside the project root.
- Supabase names are mixed case and quoted (`"Shikshaqmine"`, `"Classes Taught"`).
- Migrations: `20250122000006` and `20250122000007` each have two files with the same version prefix. Do not replay superseded migrations (see Watch out).
- Dummy and fake modes are only for previews. Dummy leave calls `setDummyMode(false)` and navigates with `?dummy=0`.
